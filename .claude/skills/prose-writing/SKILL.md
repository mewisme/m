# Prose writing

Read `PROSE.md` before editing. Preserve exact technical semantics and verify every command, output sample, compatibility statement, and performance claim.

For documentation, lead with the working command and prefer short prose plus code. For GitHub, write the smallest factual response. For release notes, state shipped behavior and limitations without hype.

Run a final pass for stale names (`nub`, `nubx`, `NUB_*`, Rust/Cargo paths), invented output, unsupported parity claims, and unresolved placeholders.
